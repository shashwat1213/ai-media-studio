# 08 — Editor: screenshots & screen recordings + text → MP4

Status: built on branch `feat/editor` (on top of `feat/motion-video`). Free: no AI, no paid API.

## What it does
A third Studio tool (`/studio?tool=editor`) for tutorial / product-demo videos:
- Upload screenshots (PNG/JPEG/WebP ≤ 15 MB) and recordings (MP4/WebM/MOV ≤ 200 MB, ≤ 10 min),
  or **record the screen in the browser** (getDisplayMedia + MediaRecorder; nothing installed).
- Timeline: clips end to end (images get a duration, videos get a trim), captions (≤ 3 lines,
  4 sizes, 3 styles, 8 colours, drag to place) and highlight boxes (drag/resize), each with a time range.
- Formats 16:9 (1920×1080), 9:16 (1080×1920), 1:1 (1080×1080); fade or cut between clips.
- Live preview in the browser (same font + same size fractions as the server render).
- Render → EDIT job → worker ffmpeg → H.264 MP4 in the gallery. 1 credit per started 5 s (max 120 s).
- Draft is saved in localStorage, so a refresh doesn't lose work.

## Architecture (reuses everything)
```
browser ──POST /uploads──────────────▶ API: PENDING row + presigned POST (policy: exact type, max size)
browser ──multipart POST (the file)──▶ S3/MinIO   (the file never passes through the API)
browser ──POST /uploads/:id/complete─▶ API: HEAD object + ffprobe over a presigned URL → READY + w/h/duration
browser ──POST /edits {timeline}─────▶ API: normalise against the user's READY uploads → reserve credits
                                         + EDIT job (spec stored as JSONB) in ONE transaction → enqueue
worker  ──download clips → ffmpeg filter graph → put MP4 → Asset + DONE (guarded) | FAILED + 1 refund
```

## Decisions (and why)
| Decision | Why |
|---|---|
| Presigned **POST**, not PUT | A POST policy lets S3 itself enforce `content-length-range` and `Content-Type`. A PUT URL can't cap size. Test: wrong Content-Type → S3 returns 403. |
| Verify with **ffprobe** on complete | Trust decoded content, never file name / browser MIME. A text file renamed `.png` is rejected and deleted. `-protocol_whitelist` stops crafted files from opening other files/URLs. |
| WebM duration fallback | MediaRecorder WebM often has no duration in the header → read packet timestamps instead. |
| Store a **normalised** spec | The API resolves the request against real uploads (exact lengths, trims clamped, overlays inside the timeline). The worker renders exactly what was priced. |
| Captions via `textfile=` + `expansion=none` | User text never enters the command line or the filtergraph: `'`, `:`, `%{pts}`, `\` are just characters (tested). |
| **One drawtext per line** | ffmpeg 8 draws `\n` from a text file as a missing-glyph box (found visually). Per-line also centres each line like subtitles. |
| Clamp includes box padding | ffmpeg silently drops a `box=1` that would cross the frame edge (found visually: 2nd line lost its box). |
| Bundled font (Geist SemiBold, SIL OFL) | Same font in the browser preview and the render → honest preview. Alpine image has no fonts. |
| DB CHECKs for EDIT rows | `kind::text` in the CHECK: Postgres forbids using a just-added enum value in the same transaction. |
| Ownership re-checked in the worker | Upload ids in the JSON are never trusted: must be the job owner's, READY, still existing — else FAILED + refund. |
| Sweeper deletes abandoned PENDING uploads after 1 h | Tab closed mid-upload must not leave rows/objects forever. |

## Verified
- API: 150 tests pass (31 new for the editor incl. real MinIO uploads, real ffprobe, S3 policy rejection,
  and an end-to-end BullMQ → ffmpeg render). Line coverage 94.5%.
- Docker: `scripts/smoke.sh` now uploads a PNG through the presigned POST, renders an edit, checks the MP4 + credits.
- Browser (Playwright, real Chrome): register → upload screenshot + WebM → add to timeline → trim 1–4.5 s →
  2-line caption → highlight → play preview → render (≈1 s for 6.5 s of 1080p) → card in feed → reload keeps the draft →
  390 px mobile has no horizontal overflow. Server frames match the preview (caption, box position, trim offset).

## Honest limits / next
- No audio (recordings are rendered silent). Next: keep mic/system audio + voice-over upload.
- Preview is approximate (browser text rendering vs. libfreetype); final positions match closely, not pixel-exact.
- Zoom-into-region and arrow shapes not built yet; blur/redact box would be useful for screenshots with secrets.

## Step 1 (smart editor): templates, cards, Ken Burns, real transitions, animated text

Goal: before any AI, the editor itself must be able to make a decent reel/slideshow, because the
AI director (step 2) only picks a template, the order, the words and the timings.

### Added
- **Spec v2** (`v: 2`; v1 jobs are refused by the worker, there were none in production):
  - **Card clips**: title/subtitle on a solid colour or diagonal gradient, generated by ffmpeg (`lavfi`),
    text fades/rises in. Used for intros and end cards.
  - **Ken Burns on stills**: zoom in/out, pan 4 ways, or `auto` (varied sequence). zoompan on a 2x
    canvas (1x stair-steps on slow pans; 4x like Motion was too slow at 1080p), smoothstep easing.
  - **10 transitions** via ffmpeg `xfade` (fade, fade-through-black, dissolve, slide L/U, smooth wipe,
    wipe, zoom-in, circle reveal, cut). Transitions OVERLAP clips, so every clip gets an `atS` and
    the total = sum − overlaps. Length = min(0.5 s, 40% of the shortest clip).
  - **Caption animation**: none / fade (alpha ramp in+out) / slide (fade + rise 4%).
  - Font size follows the frame's **short side** (9:16 text was 1.8x too big before).
- **5 templates** (`templates.ts`, plain data): Punchy Reel (9:16), Travel Story (9:16),
  Product Demo (16:9), Tutorial Steps (16:9, auto "Step N"), Square Slideshow (1:1).
  `buildFromTemplate()` is pure: intro card, pacing (optionally stretched to a target length),
  motion, fit, middle-of-recording trims, captions placed inside each clip clear of transitions, outro.
- `POST /edits/build`: template + the user's files -> a renderable draft. Not rendered, not charged.
  Validated with the same normaliser as the render, so a bad draft fails here, not in the worker.
- Web: "Start from a template" dialog (pick style, tick files in order, title), Add card, card
  inspector (title/subtitle/gradient/colour), camera-move picker, transition picker, caption animation.
  Preview shows cards, Ken Burns (CSS transforms), transitions and caption animation (approximate).

### Found while testing
- `drawtext` with an animated `fontsize` **segfaults** ffmpeg 8 → no "pop/scale" text animation; fade/slide only.
- xfade needs identical timebases on both inputs → `settb=AVTB` at the end of every clip chain.

### Verified
- 161 API tests pass (11 new: xfade chain offsets, overlap maths, short-clip transitions, motion,
  cards, animation, 9:16 font size, every template normalises, `/edits/build` auth/ownership,
  E2E template → render at 1080x1920). Lines 94.8%.
- All 10 transitions rendered with real ffmpeg on a 5-clip 9:16 timeline (≈2.2–2.9 s each).
- Browser: upload 3 photos + a recording → Punchy Reel → Build (6 clips) → preview → add a caption
  by hand → render 8.3 s 1080x1920 in ≈3 s → frames checked. No console errors; mobile no overflow.

## Step 1b: audio — voice-over from a script, speech-to-text, auto captions, music with ducking

### What it does
- **Voice-over:** write a script (≤ 3000 chars), pick one of 10 voices (play a cached sample),
  Generate → an MP3 in the library (Upload, `source = TTS`), dropped on the audio track at the
  playhead and transcribed for free. 1 credit / 500 chars, refunded if the provider fails.
- **Speech-to-text:** "Transcribe" on any video with sound or audio file → word-level transcript
  (Whisper large-v3-turbo, language auto-detected). 1 credit / started minute (free for our own
  voice-overs). Runs in the worker; the panel polls; refund once on failure.
- **Auto captions (reels-style):** word-by-word karaoke captions from a transcript, grouped into
  ≤ 3-word lines, breaking on sentence ends / pauses; spoken words turn yellow.
- **Audio tracks:** voice tracks + "As music" (starts at 0, quieter, **auto-ducks** under the voice
  via side-chain compression). Video clips keep their own sound with a volume. Silent edits stay silent.
- **Uploads:** MP3 / WAV / M4A / WebM / OGG audio (≤ 50 MB); videos now record whether they have sound.

### Free providers (verified with the project's token)
| Task | Model (Cloudflare Workers AI) | Measured |
|---|---|---|
| TTS | `@cf/deepgram/aura-2-en`, 10 voices (all respond) | ~1.5–3.3 s per paragraph |
| STT | `@cf/openai/whisper-large-v3-turbo` (word timestamps) | 4–6 s for a 7 s clip; 21 s for 126 s |
`SpeechProvider` interface: swap for local Piper / whisper.cpp later without touching anything else.
`SPEECH_PROVIDER=stub` (or no credentials) = free offline stub (tests, CI).

### Text rendering moved to libass (ffmpeg `ass` filter)
Found while testing Hindi: **drawtext does not shape Devanagari** (स्ते rendered as broken
glyphs). libass uses HarfBuzz: correct conjuncts, per-character font fallback (Latin from Geist,
Devanagari from bundled **Noto Sans Devanagari Bold**, SIL OFL), automatic wrapping, `\fad`,
`\move`, karaoke `\k`. Captions, karaoke AND card titles all go through one generated `.ass`
file. User text is escaped (`{` `}` `\`) so it can't inject override tags (tested).

### Audio mixing (ffmpeg)
Each source → 48 kHz stereo, trimmed, `adelay` to its position, padded to the video length →
`amix` (no normalisation) → `alimiter` → exact length → AAC 160k. Ducking = `sidechaincompress`
keyed by the sum of the non-music sources: measured music −32.5 dB → −42 dB under speech
(threshold 0.005, ratio 20, attack 15 ms, release 350 ms).

### Data / safety
- Migrations `audio`, `transcript_ref`, `transcript_at`: Upload gets `hasAudio`, `source`, `script`,
  `voice`, `transcript` (JSONB), `transcriptStatus/Error/Cost/Ref/At`. CHECKs: TTS rows carry
  script+voice; DONE has a transcript; PENDING has a cost; paid transcriptions have a ledger ref.
- Exactly-once refunds: guarded `PENDING → FAILED` + the ledger's one-REFUND-per-refId index; a
  fresh ref per request so a retry after a refunded failure is refunded too (tested).
- Stuck PENDING transcriptions are swept and refunded after the job timeout.
- Spec v3: v2 specs are refused by the worker (none in production).

### Verified
- API: 186 tests pass (25 new in `audio.test.ts`), lines 95.2%, branches 83.1%.
- Real providers, browser (Playwright, Docker stack): Travel Story template → script →
  voice-over (Orion) 3.3 s → transcript 4–6 s, word-perfect → auto captions → ducked music →
  render 10.4 s 1080x1920 in ≈6 s. The final MP4 has AAC stereo 48 kHz; Whisper on the FINAL
  file hears the exact script; karaoke frames checked visually. No console errors.

### Honest limits
- Voices are **English only** (Aura-2-en). MeloTTS on Workers AI has no Hindi. Hindi/Hinglish
  voice needs a paid provider or a local model (e.g. AI4Bharat Indic-TTS) — next decision.
- Hindi **transcription** depends on Whisper's Hindi quality; not yet tested on real Hindi speech.
- Preview audio sync is approximate (browser `<audio>` elements follow the clock within 0.3 s).
